# Independent normalization

`normalization.metadata` accepts JSON/YAML; relative metadata paths resolve against the physics configuration file. Relative explicit EVGEN paths resolve against the metadata file. No EVGEN path is inferred from a process label or RECO filename, and no tape recall is launched.

For simulation, list components with a distinct `piece_id`, a common generation `ensemble`, `generated_events_represented`, `count_convention`, `weights: unit`, `unit_weight_convention_confirmed: true`, and a unit-labelled cross section. Multiple pieces require `disjoint_generated_pieces: true`; alternative reconstructions of identical generator events are not disjoint. Different ensembles or undocumented overlap produce component results with no combined exposure. Weighted/signed/unknown conventions are explicitly unavailable; no generic sum(weights)/sigma assumption is implemented. Preserve any supplied sums/weight-convention metadata in the component record.

An explicit `evgen_file` activates the supported HepMC3 ROOT reader: only the final event's GenCrossSection event attribute (attribute_id=0) and weights are read from the latest `hepmc3_tree`. No particle branches or all-event scan is used. Cross section/error are pb by HepMC3 convention. Zero stored error is not proof of zero uncertainty. A final representative weight of [1] is checked, but the user still must confirm the generator's run-level unit-weight convention and supply the generated count represented by this RECO subset. A running/partial file must not be described as final metadata. Unsupported schemas produce unavailable normalization and a reason.

`L[pb^-1]=N_generated_represented/sigma[pb]` applies only under that confirmed convention. Values using unskimmed/no-loss assumptions must be `precision: approximate` and list assumptions. The producer records processed/available reconstructed rows separately and never substitutes them for the generated numerator. Known filtering/loss interpretations belong in count_convention; no efficiency is invented. Supplied metadata apply to the complete input sample, not its training fraction or selected pi0 count. The caller is responsible for matching component identities to the input manifest.

For real data, provide recorded and/or delivered luminosity with units and source/run bookkeeping, plus `use: recorded_luminosity` or `delivered_luminosity`. Elapsed time and live time remain independent metadata fields. `kind: reported_exposure` accepts an independently established exposure (the DIS regression example uses this mode); it does not claim the generator reader established it anew.

Supported cross-section units: pb, nb, ub, mb, b. Luminosity: nb^-1, pb^-1, fb^-1. Results include all three. Ideal equivalent time is `L[pb^-1]*1e36/Linst[cm^-2 s^-1]`; defaults are 1e33 and1e34. These are luminosity-equivalent seconds/minutes/hours, not elapsed acquisition time or assumptions about accelerator/DAQ duty factor. Missing or ambiguous normalization never changes the gain solve.
